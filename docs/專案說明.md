# 工資對帳存證（wage-proof）專案說明

MetaEarth Hackathon 2026: BEACON 台灣站｜賽道：AI 與信任基礎設施

## 一句話

勞工發現薪資單少算時數，把比對報告的指紋登記到 ME Network，指名雇主在期限內回應：確認就用 MEC 當場補發差額，不同意就留下理由，不回應就由合約記為逾期。雇主沒有 ME ID 真人驗證，合約直接拒絕登記。

English: Workers register a fingerprint of their payslip-vs-attendance report on ME Network and name the employer. The employer must answer before the deadline: confirm and pay the shortfall in MEC in the same transaction, or dispute with a reason. Silence is recorded as expired. The contract itself checks the employer's ME ID and refuses employers who are not verified humans.

## 要解決的問題

欠薪是台灣勞資爭議裡最多的一種。勞動部統計，民國 112 年（2023）勞資爭議 25,731 件，其中積欠工資 10,815 件，占 42%，加班費也算在裡面（[勞動部新聞稿，2025-01-03](https://www.mol.gov.tw/1607/1632/1633/77731/)）。

這類爭議一開始常卡在兩件事：

- 勞工手上的截圖和試算表，可以被說成事後做的。
- 雇主可以說「沒收到」「不知道」，勞工很難證明對方哪一天已經知道差額。

缺的是一份雙方都改不了的紀錄：勞工哪一天提出哪份報告、指名了誰、雇主在期限內有沒有回應、怎麼回應。

## 給誰用

| 角色 | 在系統裡做什麼 |
|---|---|
| 勞工 | 打卡紀錄和薪資單對不上時，登記比對報告的指紋，指名雇主、設定回應期限 |
| 雇主或人資 | 在期限內確認（同一筆交易補發 MEC）或異議（留下理由的指紋） |
| 調解人、工會、律師 | 拿到報告檔自己算指紋，對到鏈上那一筆，看雙方做了什麼、在哪個區塊 |

## 核心功能

一筆紀錄只有四個動作，誰能做、什麼時候能做，全部由合約判斷：

| 動作 | 誰能做 | 合約檢查 |
|---|---|---|
| 登記（報告指紋、雇主、期限、主張的補發金額） | 勞工 | 雇主的 ME ID 至少「真人驗證」；期限 30 秒～90 天；指紋格式 |
| 確認並補發 | 只有被指名的雇主 | 期限內、還沒結案；附上的 MEC 要剛好等於主張金額，合約轉給勞工 |
| 異議（理由指紋） | 只有被指名的雇主 | 期限內、還沒結案 |
| 記為逾期 | 任何人 | 期限已過、還沒結案 |

每筆紀錄存的是：報告指紋、雙方地址、登記當下雙方的 ME ID 等級、登記與期限時間、狀態、補發金額。薪資單和出勤紀錄本身不上鏈，只在勞工手上。

## ME Network 用在哪裡

1. **合約跑在 ME Network 上。** CosmWasm 合約部署在 ME 測試網 ME-Hub（code id 22，`me1gsy3cm2n5mnmv9esz5ysm7np3xgxryktjmfgu22jldfwps2u3rks38x2yg`）。建立時 admin 留空，沒有人能改規則或改紀錄。
2. **ME ID 由合約自己查。** 登記時，合約向 ME Network 的身分模組查雇主等級，低於「真人驗證」就回 `EmployerNotVerified`，交易失敗、不產生紀錄。查到的等級寫進紀錄。這條規則在鏈上執行，示範網站的伺服器改不了。合約查身分的能力在 ME Hub 主線 11-06 才加入，測試網升級後我們就接上了。
3. **MEC 用來結算。** 雇主確認差額時，同一筆交易把 MEC 補發給勞工，「承認」和「付款」不會分開發生。附的金額要剛好等於勞工主張的數字，少一點或多一點合約都拒絕；異議和登記附了錢也拒絕，所以錢不會卡在合約裡。示範用固定換算 NT$1＝0.00001 測試 MEC（不是真實匯率），報告裡少算的 NT$523 就補發 0.00523 MEC。
4. **網頁直接讀鏈。** 紀錄列表、倒數、每一步是誰簽的、哪個區塊、手續費多少，都是瀏覽器直接向 ME 測試網 Hub REST 查的，每一項都附查證連結。

ME ID 在這裡擋的是假雇主：如果任何地址都能當雇主，勞工或第三人可以開一個帳號自己按「確認」，做出一份假的承認紀錄。要求雇主是通過驗證的真人，這份紀錄才有人負責。

## 為什麼要放在鏈上

- **時間點兩邊都改不了。** 勞工事後換報告，指紋就對不上；紀錄指名了雇主的地址，登記時間和期限都照區塊時間算。勞工、雇主、調解人看的是同一份公開紀錄，不用相信任何一方的資料庫。
- **逾期不用人判斷。** 期限一過，誰都能把它記為逾期，雇主之後想回應會被合約拒絕。

## 評審試用（約 3 分鐘）

網址：**https://wage-proof.vercel.app/**　不用錢包、不用領幣。伺服器用兩個只有測試幣的示範帳號代簽，誰能做什麼仍由合約判斷。

1. 打開網頁，左邊是勞工的手機，中間是老闆的手機，右邊「鏈上發生了什麼」先列出這份合約最近的真實交易（螢幕較窄時移到手機下方；手機寬度用上方「勞工｜老闆」切換）。兩支手機上方一行字會說現在該按哪裡。
2. 按左邊的「請老闆補發 NT$523」。約 5～10 秒出塊，中間老闆的手機收到補薪單，左邊變成「等老闆回覆」並倒數。
3. 按中間的「補發 NT$523」：同一筆交易從老闆帳號付 0.00523 MEC，合約轉給勞工；左邊顯示勞工帳戶補發前後的餘額。或按「我有異議」，寫一句理由，按「送出異議」，不付款。
4. 按「再送一張」，再按「試試看：沒有 ME ID 的公司」，然後按「請老闆補發 NT$523」。合約會擋下，畫面寫出被擋的原因，並附一筆同樣被拒、已經上鏈的交易。
5. 想看逾期：回覆期限選「30 秒」，送出後不要回覆，到期後按左邊的「記為逾期」。

桌機從打開網址到老闆補發完成只要按兩下，不用捲動。手機寬度也能操作。

## 怎麼做的

| 在哪裡 | 做什麼 |
|---|---|
| 瀏覽器（鏈下） | 讀比對報告、算 SHA-256 指紋、直接向 Hub REST 讀合約與交易 |
| 示範伺服器（Vercel） | 先在節點上模擬交易，合約會拒絕就不送；再用示範帳號簽名送出；有頻率限制 |
| ME-Hub 上的 CosmWasm 合約（鏈上） | 查 ME ID、檢查期限與身分、轉 MEC、存紀錄 |

技術：Rust（CosmWasm）、Node.js、CosmJS、原生 JavaScript 網頁。
